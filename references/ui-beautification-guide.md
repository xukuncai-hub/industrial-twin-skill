# Industrial Web SCADA / Digital Twin HTML 美化规范 (UI Beautification Skill)

本规范作为 `industrial-twin-skill` 的内置前端视觉与交互美化子技能，专门用于消除“AI 味 SaaS 卡片模板感”，打造具备**真实工业软件（Siemens WinCC Unified / ISA-101 高性能 HMI / 现代精密工控台）质感**的 2D / 2.5D / 3D 数字孪生上位机界面。

---

## 1. 核心反模板红线（严禁出现的“AI 廉价感”特征）

在生成 `index.html`、`styles.css` 与画布渲染代码时，**严禁**出现以下通用 AI 模板套路：
1. **禁止“套娃圆角卡片墙”**：不要把所有数据、按钮、状态都塞进一模一样的 `border-radius: 12px` + 渐变描边 + 阴影的 SaaS 卡片里，切忌左右塞满厚重侧边栏把产线画布挤扁。
2. **禁止滥用全大写眉标与中点拼接**：不要在每个区块顶部堆砌 `ALL CAPS EYEBROW` 或 `A · B · C · D` 拼接的装饰性元信息。
3. **禁止“霓虹赛博朋克”滥用**：工业上位机不是电竞大屏！高饱和青/紫渐变光晕会淹没真正的报警信号。遵循 **ISA-101 高性能 HMI 原则**：平时界面沉稳克制，**高饱和色彩只留给运行状态、传感器触发与故障报警**。
4. **禁止单调纯黑死背景**：避免 `#000000` 或毫无层次的近黑平面，应使用有物理深度的精密工业深灰/石板蓝（如 `#0D1117`、`#111622`、`#161D2B`）或高对比度现代浅灰工控主题。

---

## 2. 视觉层次与布局黄金法则

### 2.1 画布绝对主角原则（Viewport-First 80/20 法则）
- **产线视口占主导**：2.5D / 3D 产线画布应占据视觉中心（全屏铺满或 ≥ 75% 空间），信息面板以**轻量悬浮玻璃条（Floating HUD）**或**紧凑边缘停靠栏（Slim Dock）**贴边呈现，绝不喧宾夺主。
- **留白与呼吸感**：宁可少放 2 个装饰指标，也要保证设备轮廓、运动轨迹与数据读数之间有充足留白。

### 2.2 字体与数据排版（Tabular Precision）
- **等宽数字对齐**：所有实时变化的数值（坐标 `mm`、速度 `RPM`、温度 `°C`、产量 `PCS`、扫描周期 `ms`）必须设置 `font-variant-numeric: tabular-nums;`，防止数值跳动导致界面抖动。
- **字号层级分明**：核心 KPI 数值大而清晰（`24px–32px`），单位缩小弱化（`11px–12px` 次要灰度），标签简短直白（直接写“产量”“节拍”“电机 M1”，不要中英混杂硬凑长句）。

### 2.3 色彩与材质系统（ISA-101 工业语义色）
- **基底**：深石板灰 `#0E131B` + 面板半透层 `rgba(20, 27, 39, 0.78)` + 极细 1px 分隔线 `rgba(255, 255, 255, 0.08)`。
- **设备材质（2.5D / 3D）**：工业铝型材使用冷银灰明暗面（顶面 `#64748B` / 左侧 `#475569` / 右侧 `#334155`），输送带使用哑光深炭灰 `#1E2530`，配合地面柔和投影与工位高光，形成真实立体体块感。
- **状态语义**：
  - 正常/运行：`#10B981`（翡翠绿，低面积点缀）
  - 传感器/信号激活：`#38BDF8`（精密天蓝）
  - 警告/动作中：`#F59E0B`（琥珀黄）
  - 急停/故障：`#EF4444`（工业红）

## 3. 生成前两步审查流程（Plan → Build → Screenshot Critique）

1. **先定视觉方案再写代码**：动手写 `index.html` 前，先明确 4–5 个核心色值、主视口占比、需要展示的核心 I/O 信号（精选 4–8 个最关键信号，拒绝堆砌）。
2. **截图自检（强制）**：生成或修改上位机页面后，若环境支持浏览器截图，**必须实际打开页面截图并肉眼检查**：
   - 标注引线是否重叠或被边缘裁切？
   - 文字与数据是否清晰易读、无溢出？
   - 整体是否像一套“能直接放在产线大屏/工程师桌面的真工业软件”，而不是拼凑的网页卡片？
